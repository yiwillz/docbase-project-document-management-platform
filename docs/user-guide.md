## 1. 入门

### 1.1 docbase 是做什么的

docbase 按客户的 MDL（Master Document List，应交文件清单）管理一个总包项目"应该交哪些文件、交了没有、客户批了没有"：

- 在平台里建好**项目结构**（里程碑 → 文件种类）和**设备清单**，平台自动算出每一个**应交项**；
- 文件存进来时**自动命名、自动升版**，按设备 / 模块归档，并自动标出每一项**收到没有**；
- 通过**传送单**记录提交、录入**客户回复**，状态自动更新；
- 随时导出给客户的 **MDL**、给供应商的**缺件清单**，一键打**交付包**。

### 1.2 登录

1. 在浏览器（Chrome 或 Edge）打开管理员告诉你的地址，如 `https://192.168.1.50`。
   - 第一次打开如果提示"连接不是私密连接"，说明这台电脑还没装平台的证书，请找 IT 安装（见安装手册"证书"一节）。
2. 输入**用户名**和**密码**，点**登录**。
3. 登录页右下角可以切换**中文 / English**。

注意：
- 密码连续输错 5 次会锁定 5 分钟。
- 12 小时不操作会自动退出，需要重新登录；登录后会回到原来的页面。
- 忘记密码请找系统管理员重设。

### 1.3 界面布局

```

│ docbase 项目文件管理平台  [选择项目 ▼]            [中文 ▼]  [用户名 ▼] │ ← 顶栏
├────────────┬───────────────────────────────────────────────────────┤
│ 应交矩阵    │                                                       │
│ 文件浏览    │                                                       │
│ 智能投递    │                 内容区                                 │
│ 存量导入    │                                                       │
│ 交付与基线  │                                                       │
│ 项目结构    │                                                       │
│ MDL        │                                                       │
│ 传送单      │                                                       │
│ 闭环与关闭  │                                                       │
│ 设备        │                                                       │
│ 变更记录    │                                                       │
│ 设置        │                                                       │
└────────────┴───────────────────────────────────────────────────────┘
   左侧菜单（进入项目后才有；没有权限的菜单不显示）
```

- **顶栏**：点"docbase"回到项目列表；**选择项目**下拉框直接切换项目（停留在同一个功能页）；语言切换；点**用户名**打开用户菜单（修改密码、退出登录；系统管理员还有"用户管理"；最下面是版本号）。
- **页面顶部的提醒条**：
  - 红条"文件存储不可用"：存文件的磁盘断开了，暂时不能上传，接好后自动恢复。请通知 IT。
  - 黄条（只有系统管理员看到）：备份没配置、最近一次失败或超过 2 天没成功。
  - 灰条"只能查看"：项目已归档，或你在这个项目里没有修改这一页的权限。
- 所有表格都可以点表头排序、拖动列宽；带"导出"的地方会下载 Excel 或 PDF。

### 1.4 修改密码

用户名 → **修改密码** → 输入原密码、两次新密码（至少 8 位）→ **保存**。改完后，你在其他电脑上的登录会失效。

### 1.5 角色和权限

每个人在每个项目里有一个角色；只有项目成员能看到这个项目。

| 能做的事 | 项目管理员 | 成员 | 只读 |
|---|:-:|:-:|:-:|
| 查看、下载、预览单个文件；看变更记录 | ✔ | ✔ | ✔ |
| 上传、归类、移动文件 | ✔ | ✔ | |
| 改应交项状态、传送单、客户回复、阶段基线 | ✔ | ✔ | |
| 导出 MDL、缺件清单、交付包、变更记录；发 MDL 给客户 | ✔ | ✔ | |
| 项目结构、设备、设置、命名模板 | ✔ | | |
| MDL 导回、设备清单导入 | ✔ | | |
| 存量导入、关闭 / 重新打开里程碑 | ✔ | | |
| 管理成员、归档项目 | ✔ | | |

**系统管理员**另外能看到所有项目、新建项目、删除空项目、管理用户。

## 2. 快速上手：一个项目从头到尾

下面是一个项目的典型流程，每一步的详细说明在后面的章节。

| # | 谁 | 做什么 | 在哪 |
|---|---|---|---|
| 1 | 系统管理员 | 新建项目，把项目管理员加为成员 | 项目列表 → 新建项目；设置 → 成员 |
| 2 | 项目管理员 | 填项目信息、MDL 表头、客户审核期限 | 设置 → 项目信息 |
| 3 | 项目管理员 | 建里程碑和文件种类（可从别的项目复制、从 Excel 粘贴） | 项目结构 |
| 4 | 项目管理员 | 导入设备清单 | 设备 → 导入 Excel |
| 5 | 项目管理员 | 给"按设备"的文件种类勾选对应设备 → 平台生成应交项 | 项目结构 → 设对应设备 |
| 6 | 项目管理员 | 按客户的叫法设置审核代码 | 设置 → 审核代码 |
| 7 | 项目管理员 | 发第一版 MDL（Rev.0）给客户 | MDL → 发给客户 |
| 8 | 成员 | 日常存文件：拖进来，平台识别位置并命名 | 智能投递；或应交矩阵里"上传" |
| 9 | 成员 | 提交给客户：勾选应交项生成传送单 | 应交矩阵 → 生成传送单 |
| 10 | 成员 | 客户回复后录入审核代码 | 传送单 → 录入客户回复 |
| 11 | 成员 | 跟进缺件、逾期；把缺件清单发给供应商 | 应交矩阵 → 缺件清单 |
| 12 | 项目管理员 | 阶段结束：冻结基线、检查闭环、关闭里程碑 | 交付与基线；闭环与关闭 |
| 13 | 成员 | 打交付包交给客户 | 交付与基线 → 交付包 |

已经有大量旧文件的项目，在第 5 步之后用**存量导入**把旧文件一次导进来（第 14 章）。

## 3. 项目

### 3.1 项目列表

登录后的首页。每个项目一行：

| 列 | 说明 |
|---|---|
| 完成率 | 已批准 ÷ 应交（不算不适用的）；没有应交项时显示"—" |
| 缺件 | 还要我方或供应商交东西的应交项数：还没收到文件的（不算已批准、不适用的）+ 客户要求修改重交的；**点数字**进入应交矩阵并筛好 |
| 逾期 | 未提交且过了截止日的应交项数（红色）；**点数字**进入应交矩阵并筛好 |
| 待归类 | 存进来但没识别出位置的文件数；点数字进入"智能投递 → 待归类" |
| 状态 | 进行中 / 已归档 |

- 搜索框按编号、名称、客户搜索；勾选**显示已归档**显示归档的项目。
- 双击一行或点**进入**打开项目。
- 你只能看到自己是成员的项目。

### 3.2 新建项目（系统管理员）

**新建项目** → 填**项目编号**（唯一，如 P-001；不会进文件名，只用作交付包最外层文件夹）、**项目名称**、客户名称、总包名称 → 确定。

建好后：
1. 到 **设置 → 成员** 把项目管理员加进来；
2. 到 **项目结构** 建结构，或从已有项目复制（4.6 节）。

### 3.3 归档

项目结束后由项目管理员归档：项目列表里点**归档**，或 **设置 → 项目信息** 最下面的**归档**。

归档后所有页面只能查看、下载，可以随时**取消归档**。

### 3.4 删除项目（系统管理员）

只有**空项目**能删除，比如建错了、建重复了的项目。空项目是指：没有文件、没有传送单、没发过 MDL、没有阶段基线、没做过存量导入。

1. 项目列表里点那一行的**删除**；
2. 能删的：输入项目编号确认（可以写原因）→ **删除**。项目结构、设备、成员、配置和它们的变更记录一起删掉，**不能恢复**；变更记录里会另留一条"删除了这个项目"的记录；
3. 不能删的：对话框里会列出原因（如"文件 12 份"），这种项目请**归档**。

## 4. 项目结构

项目结构就是平台里的 MDL：**里程碑 → 文件种类**，文件种类可以按**模块**分区、按**设备**展开。平台是 MDL 的唯一来源，给客户的 MDL Excel 从这里导出（第 11 章）。

页面布局：左边是里程碑列表，右边是选中里程碑下的文件种类表格。

### 4.1 里程碑

- **新建里程碑**：填名称、目标、截止日期、说明。编号自动生成（M1、M2…），不能手填。
- 点选里程碑后右边显示它的文件种类；里程碑卡片上显示截止日期和种类数。
- 可以编辑、调整顺序、删除。删除只在下面没有文件种类时可以，后面的编号会往前补。

### 4.2 文件种类

在右边表格里直接编辑常用字段：

| 列 | 说明 |
|---|---|
| 编号 | 自动生成："里程碑号.序号"，如 3.1、3.2…3.10。按文本处理，3.1 和 3.10 是两个不同的种类 |
| 名称 | 如 Equipment datasheet |
| 分类 | 选填，自己定的分组 |
| 要求类别 | **合同规定** / **客户要求**（合同外的新增要求）/ **内部要求**（不给客户看） |
| 按设备 | 打开后每个对应的设备条目一个应交项 |
| 模块分区 | 选了模块后每个模块一个应交项 |
| 对应设备 | 按设备的种类对应哪些设备 |
| 截止日期 | 空着时用里程碑的 |
| 进客户 MDL | 关掉就不出现在给客户的 MDL 里；内部要求一律不进 |
| 依据 | 合同条款，或客户提出要求的函件号 |

添加和排序：
- 在表格最下面的输入框里输入名称、回车，就新建一个种类。
- 想插在某一行前面：点那一行的**在这一行前面插入**，后面的编号自动往后挪。

**详情**里还有不常用的字段：要求日期、变更日期、变更依据、接受情况（客户要求才有：待确认 / 接受 / 不接受 + 接受依据）、变更单号、MDL 备注、应含内容、说明、目的、**识别关键词**。

**识别关键词**：供应商文件名里对这个种类的常见叫法，如 Datasheet 的"DS""cut sheet"。智能投递靠它认出文件属于哪个种类，填得越全，识别越准。

注意：
- **客户要求**的种类，接受情况选"不接受"后，它的应交项自动变为不适用，客户 MDL 里显示"不接受：依据"。
- **删除和停用**：没用过的种类可以**删除**。用过的（挂了文件、进过传送单或阶段基线）不能删，点删除时会说明原因，并可以直接**改为停用**。勾选**显示已停用**能看到停用的。
- 编号变动会影响已挂文件的种类时，插入或调整顺序会被拒绝；删除时留空号。

### 4.3 从 Excel 粘贴多行

**从 Excel 粘贴多行** → 在 Excel 里选中几行复制 → 粘贴（Ctrl+V）→ 确定。

- 第一行是表头时按表头对列，否则按提示的列顺序。
- 只有名称必填；要求类别填 合同规定 / 客户要求 / 内部要求；按设备填 是 / 否；日期写成 2026-06-07。

### 4.4 模块分区和对应设备

- **模块管理**：项目内共用的模块。可以改名、调顺序、停用、**删除**；用过的模块不能删，会提示改为停用。
- **设模块分区**：勾选几个种类 → 设模块分区 → 选模块。在分区里输入新名字也会直接新建模块。
- **设对应设备**：勾选几个"按设备"的种类 → 设对应设备。
  - **怎么选**：全部设备 / 按设备种类 / 按模块 / 逐个选；
  - **方式**：替换 / 加上 / 去掉。

改完后平台自动重算应交项：多出来的新建，不再需要的作废（作废的保留历史）。

### 4.5 标准模板

- **下载标准模板**：平台统一格式的 Excel 结构模板。
- **导入标准模板**：按模板填好的结构，导入前先预览，确认后才写入。

### 4.6 从其他项目复制结构

**从其他项目复制结构** → 选源项目 → 确定。

- 复制的是定义：里程碑、文件种类、模块、分区、设备种类和模块对应的设备种类。
- 不复制设备、状态和日期。
- 当前项目必须还没有里程碑和模块。

## 5. 设备

设备按"条目 + 台数"记录，一类设备一个条目；应交项按条目算，不按台。

### 5.1 设备条目

表格列：设备编号、设备名、设备种类、供应商、台数、别名。

- **设备编号**选填：有编号的项目内唯一、不复用；没编号的用名称区分，文件名里也不带编号。
- **别名**：设备的其他叫法，智能投递识别用。
- 展开一行可以填每台的**出厂编号**：一行一台，可以从 Excel 整列粘贴。只有填了的台才有记录。
- **新建设备**、**编辑**、**停用**、**删除**：
  - **没用过**的设备可以删除，编号释放，可以重新用（适合录错、建重复的）；
  - **用过**的设备只能停用，编号仍然占着，不会被复用。点删除时会说明原因（如"传送单 1 张"），并可以直接**改为停用**。
  - "用过"是指：它的应交项挂了文件、进过传送单或阶段基线，或者最近一次发 MDL 给客户时它已经存在（客户见过这个编号）。
  - 勾选多台后点**删除选中的 N 项**：没用过的删掉，用过的列出原因，再问要不要一起停用。

### 5.2 导入设备清单 Excel

1. **下载模板**看格式（也可以直接用你们自己的清单）。
2. **导入 Excel** → 选文件 → 进入**导入预览**：
   - 平台自动找表头行、认列。认得不对的列，在"对应到"里改（设备编号 / 设备名 / 设备种类 / 供应商 / 台数 / 别名 / 其他属性 / 忽略），再点**重新预览**；
   - 预览列出新增 / 修改 / 重新启用 / 清单里没有了 / 没变；
   - 清单里有新的设备种类时会提示"会新建设备种类"；
   - "清单里没有了"的设备默认只提示，勾选后才一起停用。
3. 确认导入。

说明：
- 清单里其他的列原样保存为设备属性。
- 再次导入时，有编号的按编号对上，没编号的按名称对上。
- 也可以用**从 Excel 粘贴多行**，同样先预览再确认。

### 5.3 历史和恢复

点设备的**历史**看每次修改（字段、修改前 → 修改后、谁、什么时候、原因）。点**恢复到这次修改之前**，把那次改过的字段改回去，恢复本身也会留记录。

设备改名后，已有文件显示的名字会自动按新名字变，历史版本保留原名。

### 5.4 设备种类与模块

**设备种类与模块** 标签页：
- 管理设备种类。交付包按设备种类分一级文件夹。
- 设置**模块对应的设备种类**。按设备的种类分了模块时，设备按它的种类归到对应模块。

## 6. 项目设置

### 6.1 项目信息

- **基本信息**：项目编号、名称、说明、客户名称、总包名称。
- **MDL 表头**：MDL 文件编号（空着时用"项目编号-MDL"）、编制、审核、批准人。导出 MDL 时写在表头。
- **客户审核**：客户审核期限（天）。提交后超过这么多天没回复，标"客户超期未审"；空着表示不限。
- **编号**：里程碑代码前缀（默认 M）、传送单编号前缀（默认 TR，传送单号如 P-001-TR-0001）。
- **归档**：见 3.3。

### 6.2 审核代码

客户审完给的结论标记，如"1 批准 / 2 带意见批准 / 3 修改重交 / 4 仅供参考"，各家客户叫法不同。每个代码设：

- 英文名称、中文名称；
- **平台状态**：已批准 / 需修改重交 / 客户审核中 / 不适用；
- **最终批准**：关掉的（如带意见批准）算"已批准"，但闭环检查时要求拿到最终批准；
- **别名**：识别客户退回文件时用的其他写法。

整体保存，旧的设置留历史。

### 6.3 状态映射

MDL 导回、标准模板导入时，把状态文字（如"Pending client approval"）翻译成平台状态。

- 每条规则包括：状态文字、匹配方式（等于 / 包含 / 正则）、平台状态、责任方、是否明确、优先级（数字小的先匹配）。
- 不区分大小写。
- 下面的**试算**框里输入一段文字，可以看会被认成什么。

### 6.4 命名模板

文件名的格式。页面上方的"怎么填"里有同样的说明，可以收起。

**每一行管哪种文件**：

| 行 | 用于 |
|---|---|
| 按设备 | 按设备的文件种类，设备有编号（最常见） |
| 按设备（没编号） | 按设备的文件种类，设备没有编号 |
| 按设备，多份文件 | 同一台设备下有好几份不同的文件（如几张图），用标题区分 |
| 按设备（没编号），多份文件 | 同上，设备没有编号 |
| 不对应设备 / 按模块 | 不对应设备的、按模块分区的文件种类（模块名不进文件名） |

**占位符**：模板里花括号的部分会换成实际的值，其他文字（如 `_` `-` `.` `V`）原样保留。

| 占位符 | 换成 | 示例 |
|---|---|---|
| `{no}` | 编号：里程碑号.种类号 | 3.5 |
| `{tags}` | 设备编号；一个文件挂几台设备时用连接符连起来 | 72、72&73 |
| `{type}` | 文件种类名称 | Cut sheet |
| `{equipment}` | 设备名称；几台设备名字不同时用连接符连起来 | machine1 |
| `{title}` | 文件标题：取自原文件名，去掉版本号和日期 | Wiring diagram |
| `{date}` | 文件日期，按"日期格式"写 | 20260226 |
| `{version}` | 平台版本号，只写数字（模板里的 V 是普通文字） | 1 |

**怎么改**：
1. 在要改的那一行里输入新的格式。空着的行用默认格式（输入框里的灰字就是默认）。
2. 写错时（如少了 `{version}`、占位符拼错）下面会马上提示，**保存**按钮也点不了。
3. 填写原因，点**保存**。保存后，到文件浏览里看已有文件的名字，确认是想要的样子。

常见改法（以"按设备"为例）：

| 想要 | 填 | 结果 |
|---|---|---|
| 日期放最前面 | `{date}_{no}.{tags}_{type}-{equipment}-V{version}` | 20260226_3.5.72_Cut sheet-Mixer A-V1.pdf |
| 不要设备名 | `{no}.{tags}_{type}-{date}-V{version}` | 3.5.72_Cut sheet-20260226-V1.pdf |
| 版本写成 Rev1 | `{no}.{tags}_{type}-{equipment}-{date}-Rev{version}` | 3.5.72_Cut sheet-Mixer A-20260226-Rev1.pdf |

把"填"一栏的内容复制到"按设备"那一行即可。

**其他设置**：
- **识别不出时的前缀**：进待归类的文件保持原名；填了（如 x）就加在原名前面，默认不加。
- **多台设备的连接符**：默认 `&`（如 72&73）。
- **日期格式**：20260226 / 2026-02-26 / 260226 / 26022026。
- **文件名最长**：整个文件名（不含扩展名）最多多少个字符，超了先截短标题，再截设备名和种类名。

**注意**：
- 每一行都必须含 `{version}`，否则不能保存。
- 不会自动改大小写；Windows 不允许的字符（如 `/ : * ?`）会自动去掉。
- 保存后，新上传的文件按新格式命名，已有文件显示的名字也会跟着变（每个版本上传时的名字另外保留）。
- **全部恢复默认**可以回到默认模板。

## 7. 存文件

有两种方式：位置已知时**直接上传**，一堆文件时用**智能投递**。上传没有必填表单，平台自动命名。

### 7.1 直接上传（位置已知）

在**应交矩阵**的某一行点**上传**，或在**文件浏览**的某个文件夹里点**上传到此处**：

1. 拖入或选择文件。
2. 平台显示**存为**：新文件 V1，或某个已有文件的新版本 V2；显示命名预览。
3. 按需调整：
   - **来源**：供应商 / 我方 / 客户；
   - **标题**：一项下有好几份文件时用来区分；
   - **文件日期**：默认取自文件名里的日期 → 文件修改时间 → 上传日，也可以手动填。
4. 点**存入**。

几台设备共用一份文件（如一份数据表覆盖 72、73 两台）：在应交矩阵里勾选同一种类下的几台设备 → **上传到这几项**。文件名里设备编号会用 & 连接，如 3.5.72&73。

注意：
- **项目里已有内容完全相同的文件时，会被拦下**，不能重复存。
- 上传后这一项的**收集情况**立即变为"已收到"（8.1），但**不会改提交状态**：提交状态表示和客户之间走到了哪一步，由传送单和客户回复决定（第 10 章）。

### 7.2 智能投递（一堆文件）

**智能投递** → **投递** 标签：

1. 可选：写一句**描述**（如"Vendor A 的设备数据表"）；选**供应商**后只在这家的设备里找。
2. 把文件或整个文件夹拖进来，或点**选择文件** / **选择文件夹**。
3. 平台逐个识别：
   - 根据描述、文件夹名、文件名里的种类编号、设备编号、设备名、别名、识别关键词，优先匹配"还没交"的应交项；
   - 每个文件显示：识别出的位置、置信度（高 / 中 / 低 / 待归类）、依据、命名预览；
   - 不对的话点**选应交项**改位置，或选**不存**。
4. 点**全部存入**。

说明：
- 识别不出的文件存进**待归类**，保持原名。
- 大文件自动分块上传；网络断了可以接着传，不用从头来。单个文件最大 2 GB。
- 客户退回的带审核章的文件：如果描述、文件名或文件夹名里能认出审核代码（如"Code 1"），会提示"同时记客户回复"，存入时一并录入回复。写了传送单号的记到那张传送单；没写的记到这一项最近一张还没回复的传送单。

### 7.3 待归类

**智能投递 → 待归类** 标签列出没有位置的文件。点**归类** → 选应交项 → 确定，文件名会按命名规则重新显示。

目标位置已有同样的文件时不能归类，请在那一项"上传新版本"。

## 8. 应交矩阵

项目的主工作台：每个应交项现在什么状态、谁该做、是否逾期。

### 8.1 顶部汇总

| 卡片 | 说明 |
|---|---|
| 完成率 | 已批准 ÷ 应交（不算不适用的） |
| 收集率 | 已收到文件的 ÷ 应交；点一下只看**还没收到**的 |
| 缺件 | 还没收到文件的（不算已批准、不适用的）+ 客户要求修改重交的 |
| 逾期 | 截止日已过还没提交 |
| 客户超期未审 | 提交后超过客户审核期限没回复 |
| 无凭证 | 手动改成"已批准"但没有客户回复依据，或"不适用"没写依据 |
| 各方待办 | 按责任方（我方 / 供应商 / 客户 / 未指定）统计未完成的 |

- **点卡片或按钮**筛出对应的应交项，卡片会高亮；**再点一次**取消。
- 顶部的数字按当前的里程碑、模块、关键字等范围统计，**点卡片不会改变数字**。
- **按里程碑 / 模块看** 展开分组统计。

**收集情况和提交状态是两回事**：
- **收集情况**（已收到 / 未收到）：平台里有没有这一项的文件。平台按有没有文件自动判断，不用人填。
- **提交状态**（未提交、已提交、已批准……）：和客户之间走到了哪一步。由传送单和客户回复推出。

比如供应商交来的数据表存进来了，这一项就是"已收到 · 未提交"；我方审核后用传送单交给客户，才变成"已提交"。

### 8.2 筛选

里程碑、状态、模块、关键字（编号、种类、设备、供应商），**更多筛选**里还有文件种类、设备种类、设备、供应商、责任方、要求类别、**收集情况**（已收到 / 未收到）、缺件、逾期、只看进客户 MDL 的。

筛选条件会写进地址栏，可以收藏或把链接发给同事；**清除筛选**一次清掉。

### 8.3 列表视图和矩阵视图

- **列表**（默认）：按里程碑 → 文件种类 → 模块 / 设备分层，可以折叠。应交项多时，行数多的种类先收起，点开再看。
- **矩阵**：行是文件种类，列是设备或模块，格子里是状态字母：

  | 字母 | 状态 |
  |---|---|
  | A | 已批准 |
  | R | 客户审核中 |
  | S | 已提交 |
  | C | 需修改重交 |
  | N | 未提交 |
  | X | 不适用 |
  | O | 逾期 |

  格子右上角有**小圆点**的表示已收到文件。空格子表示这里不需要交。点格子改状态。

### 8.4 每一行能做什么

| 操作 | 说明 |
|---|---|
| 收集情况 | "已收到 V2"（点开看这一项的文件和版本，可以下载）或红色的"未收到"；一项下有几份文件时显示 ×份数 |
| **上传** | 见 7.1 |
| **编辑**（或双击一行） | 改状态、责任方、状态日期（真实发生的日期，如客户批准那天）、依据（如客户函件号）、自己的截止日、内部备注 |
| 勾选几行 | **批量修改**、**生成传送单**、**上传到这几项** |

注意：
- 状态一般**不用手改**，由传送单和客户回复自动推出（第 10 章）。手改成"已批准"但没有客户回复的，会标"无凭证"，闭环时会被挡住。
- 每次改动都单独留痕。
- 截止日期带 * 的是这一项自己设的，其余取文件种类或里程碑的。

### 8.5 缺件清单

**缺件清单** → 选供应商（不选就是全部）和语言 → **下载**。

缺件 = 还没收到文件的（不算已批准、不适用的）+ 客户要求修改重交的。每个供应商一张表，可以直接发给供应商；不含内部备注。

## 9. 文件浏览

### 9.1 三种视图

顶部切换：

- **里程碑 / 种类**
- **设备种类 / 设备**
- **模块**

同一份文件在三种视图里都能找到，磁盘上只存一份。左边是目录树，勾选**只看有文件的**可以隐藏空文件夹；树的最下面是**待归类**和**回收区**。

### 9.2 筛选和搜索

### 9.3 文件详情

### 9.4 上传到此处、回收区

## 10. 传送单与客户回复

应交项的状态主要由**传送单**（提交记录）和**客户回复**推出：

```
未提交 ──生成传送单──▶ 已提交 ──客户回复──▶ 已批准 / 需修改重交 / 客户审核中
```

### 10.1 生成传送单（提交给客户）

方法一：在**应交矩阵**勾选应交项 → **生成传送单**。

方法二：**传送单 → 新建传送单** → 选应交项。

然后：
1. **方式**选**在平台生成**。
2. 填主题、提交日期、发送方式（邮件 / 客户系统 / 快递 / 其他）、外部编号、备注。
3. 点**生成**。

生成后：
- 这些应交项变为"已提交"，提交日期按填的日期；
- 平台记下每项当时交的是哪几个文件版本，这些版本不会进回收区；
- 打开传送单点**导出**（Excel / PDF），发给客户。

**补记**：已经在客户系统或邮件里交过的，选**补记（已经在别处发过）**，提交日期必填。

另外，交付包勾选"作为提交"时也会自动生成传送单（13.1）。

### 10.2 录入客户回复

客户回复按整张传送单录入，不用逐个文件改：

1. **传送单** → 打开传送单 → **录入客户回复**（整张）；或勾选几项 → **录入选中 N 项的回复**。
2. 填**审核代码**、回复日期、回复编号（客户的文件号或邮件主题）、客户意见。
3. 保存。应交项状态按审核代码自动更新（对应关系在 **设置 → 审核代码**）。

其他录入方式：
- **导入客户填好的传送单**：导出的传送单 Excel 里有回复栏，客户填好后从这里导回，先看差异再确认。
- **智能投递**客户退回的带章文件，见 7.2。
- **MDL 导回**：客户在 MDL 里改的状态，见 11.3。

**视为批准**：客户超过审核期限没回复、合同规定视为批准时，勾选**视为批准**，并写合同依据。

### 10.3 传送单列表

| 状态 | 含义 |
|---|---|
| 等回复 | 还没有回复 |
| 部分回复 | 回复了一部分 |
| 已回复 | 全部回复了 |
| 客户超期 | 超过审核期限没回复 |
| 已作废 | 作废了 |

- 列表还显示已回复数、客户应回复日。
- **改表头**只改传送单表头，不影响应交项。
- **作废**要写原因；作废后应交项状态按其余的传送单重新计算。

## 11. MDL

MDL 是平台按统一格式生成的应交文件清单，参照业界常见的 Document Register 样式。

### 11.1 导出

选语言（EN / 中文）和格式（Excel / PDF，A4 横向）：

- **导出草稿（内部预览）**：不记版本，随时看。
- **发给客户**：写版本说明（如对应的发文号）→ **记版本并下载**。
  - 每次发给客户自动记一个版本：第一次是 Rev.0（合同基线），之后 Rev.1、Rev.2……
  - 结构没变时沿用上一版的版本号；
  - 版本只增不改。

MDL 的内容：
- 表头：项目、客户、总包、MDL 文件编号、版本、日期、编制 / 审核 / 批准栏、版本记录；
- 主表按里程碑分组，状态带颜色和图例；
- 按设备的种类只显示汇总和待交的模块、台数，另附逐台缺件明细；
- 只含"进客户 MDL"的种类，标出相对上一版的变化；
- 每页有"系统生成"标识。

### 11.2 版本记录和对比

**版本记录** 列出每个版本（日期、说明、操作人、内容）。可以：
- **重新导出**任意一版；
- **和当前比**：列出这一版到现在的新增 / 删除 / 修改；
- 在对比窗口里选任意两版对比。

### 11.3 导回改过的 MDL（项目管理员）

客户或同事在平台导出的 MDL Excel 里改了状态、日期、备注后：**导回改过的 MDL → 上传 Excel**。

- 先列出差异，确认后才写入。
- 只认平台导出的本项目 Excel。
- 导回的状态通过"MDL 导回"传送单记录，有据可查。

## 12. 闭环与关闭

里程碑结束时检查是否每一项都闭环了。

1. 顶部选里程碑，平台显示：能不能关闭、卡住的应交项数、提醒数、完成率。
2. **红色问题必须处理**才能关闭：
   - 未完成；
   - 审核代码不是最终批准；
   - 已批准但没有客户回复（或不适用没写依据）；
   - 客户新增要求还没确认接受或拒绝；
   - 批准后又传了新版本。
3. **橙色只是提醒**，不挡关闭：内部要求未完成、文件种类没写要求依据。
4. 下面分"文件种类的问题"和"应交项"两张表；勾选**只看有问题的**，双击一行到应交矩阵里处理。
5. 处理完点**关闭里程碑**，填关闭日期和依据（如客户确认里程碑完成的邮件号）。
   - 还有问题但要先关：**强制关闭**，写原因，平台记下当时的问题。

说明：
- 关闭只是记录，不锁定。关闭后还有改动会提示，可以**重新打开**（要写原因）。
- **导出关闭清单**：每项批准的版本、日期、凭证（Excel / PDF）。
- **导出客户新增要求清单**：合同外新增要求的提出日期、依据、接受情况、变更单号、完成情况。

关闭和重新打开只有项目管理员能做。

## 13. 交付与基线

### 13.1 交付包

1. **范围**：全部，或选里程碑、文件种类、设备（可多选）。
2. **目录结构**：
   - **按设备**：项目编号 / 设备种类 / 设备 / 文件；不对应设备的放"通用文件 / 里程碑 / 种类"；
   - **按里程碑**：项目编号 / 里程碑 / 种类 / 文件。
3. **选项**：
   - 文件夹名的语言；
   - **放客户文件**（默认不放）；
   - 版本：当前版本，或某个阶段基线冻结时的版本。
4. **作为提交**（选填）：同时生成传送单发给客户，包里的应交项变为已提交。
5. 下面显示"N 个文件，约 X MB"。点**生成交付包**。

包在后台生成，列表里显示进度，完成后点**下载**。zip 里附文件清单（每份文件的路径、文件名、版本、大小、SHA-256 等）。做好的包保留 7 天。

### 13.2 阶段基线

在某个时刻（如设计冻结、出厂前）给全部应交项拍一张快照。

- **冻结基线**：填名称、备注。记下每个应交项的状态、责任方和每份文件的当前版本，缺件也记。
  - 基线不能改、不能删；
  - 被基线引用的版本不会进回收区。
- **查看**：冻结时的状态和版本，缺件标红。
- **对比**：和现在比，或和另一个基线比。列出状态变化、新版本、新文件、文件移走、变成缺件、补交了、新增或去掉的应交项。
- **导出清单**（Excel）、**按基线打包**（跳到交付包并选好这个基线）。

### 13.3 共享盘镜像

如果 IT 配置了共享盘镜像，每份文件的最新版会自动同步到共享盘上的一个只读文件夹，目录结构和交付包"按设备"的一样。没有账号的同事也能在共享盘里看最新文件。

- 有变化时 1 分钟内同步。
- 页面显示镜像目录、上次同步时间、待同步的变化。
- **马上全部对一遍**会立即全量核对一次（项目管理员）。

## 14. 存量导入

把项目已有的大量旧文件（如共享盘上几十 GB 的文件夹）一次导进平台。只有项目管理员能用。

1. **源目录**：选 IT 允许导入的目录下的文件夹，写一句描述 → **开始扫描**。
   - 后台只读文件、算哈希，**不复制、不改动原目录**。
2. 扫描完成后下载**预演报告**（Excel，可选中文或英文）。每个文件一行：原路径、识别出的位置、新文件名、结果，结果分为：
   - 新文件；
   - 旧版（同一文件的较早版本，按原名里的 V / Rev 和日期排序，会按顺序全部导入）；
   - 本批重复、平台已有（内容相同的只导一份）；
   - 待归类；
   - 疑似新设备（文件名里的设备编号在设备清单里没有）。
3. 需要调整时，在报告**黄色的列**里改位置、改成跳过，然后**导回改过的报告**。
4. 确认没问题后点**执行导入**。
   - 后台执行，显示进度，可以**暂停** / **继续**；
   - 失败的逐条给原因。
5. 点**明细**按类别查看每个文件的结果。
6. 不满意可以**整批撤销**：删除这一批导入的版本。已经提交给客户的、导入后又被人升过版的不撤。

## 15. 变更记录

所有写操作都会留下记录，记录本身不能修改或删除：谁、什么时候、改了哪个对象、哪些字段（修改前 → 修改后）、原因。

- 按**对象类型**、**操作人**、**时间段**筛选；展开一行看字段的前后变化。
- **导出 Excel**：按当前筛选导出，每个改动的字段一行，最多 5 万行（只读用户不能导出）。

文件的操作记录也可以在文件详情里看（9.3），设备的修改历史在设备页看（5.3）。

## 17. 规则说明：命名、版本、状态

### 17.1 文件命名（默认模板）

| 文件类型 | 规则 | 例子 |
|---|---|---|
| 按设备 | 里程碑号.种类号.设备编号_种类名-设备名-日期-V版本 | 3.5.72_Cut sheet-Mixer A-20260226-V1.pdf |
| 多台设备 | 设备编号用 & 连接 | 3.5.72&73_Cut sheet-Mixer-20260226-V1.pdf |
| 设备没编号 | 里程碑号.种类号_种类名-设备名-日期-V版本 | 3.5_Cut sheet-Beta part-20260226-V1.pdf |
| 按设备、一项有好几份文件 | 加上文件标题 | 3.8.13_P&IDs-Tool A-Wiring diagram-20260302-V2.png |
| 不对应设备 / 按模块 | 里程碑号.种类号_种类名-文件标题-日期-V版本 | 3.12_Layout drawing-Cleanroom 1F-20260226-V1.pdf |
| 客户文件 | 保持原文件名 | — |
| 识别不出 | 保持原文件名，进待归类 | — |

- **日期**取文件更新日：文件名里的日期 → 文件最后修改时间 → 上传日。
- **文件标题**取自原文件名，去掉版本号和日期。
- **模块名不进文件名**。
- 名称按设置里的写法原样输出，不改大小写；Windows 不允许的字符会去掉。
- 文件名是按当前的种类名和设备名算出来的：改名后自动变；每个版本上传时的名字另外保存。
- 项目管理员可以在 **设置 → 命名模板** 里改格式。

### 17.2 版本

- 同一应交项下**标题相同、格式相同**的文件再次上传就是升版（V1 → V2 → V3…）。版本号只增不改，和原文件名里写的 Rev 无关。
- 内容完全相同的文件不能重复存。
- **保留**：供应商和我方的文件保留最新 3 版，更早的进回收区，90 天后删除文件（记录保留）；客户文件全部保留。
- 被传送单（已经交给客户的）或阶段基线引用的版本永远不进回收区。

### 17.3 应交项和状态

**应交项**怎么来的：
- 按设备的文件种类：每个对应的设备条目一个；
- 按模块分区的：每个模块一个；
- 其余：整个种类一个，下面可以挂多份用标题区分的文件。

**状态**：

| 状态 | 含义 | 一般怎么来的 |
|---|---|---|
| 未提交 | 还没交给客户 | 默认 |
| 已提交 | 交给客户了 | 生成 / 补记传送单、交付包作为提交 |
| 客户审核中 | 客户在审 | 客户回复的审核代码 |
| 已批准 | 客户批准了 | 客户回复的审核代码 |
| 需修改重交 | 客户退回要改 | 客户回复的审核代码 |
| 不适用 | 不需要交 | 手动设置（要写依据），或客户要求被标为不接受 |

**责任方**（我方 / 供应商 / 客户）表示现在等谁，改状态时会自动带出，也可以手动改。

**收集情况**（已收到 / 未收到）和状态是分开的：有没有文件，平台自动判断；状态表示和客户之间走到哪一步。

几个提醒标志：
- **缺件**：还没收到文件的（不算已批准、不适用的），或客户要求修改重交的；
- **逾期**：截止日已过、还没提交；
- **客户超期未审**：提交后超过客户审核期限没回复；
- **无凭证**：手动标已批准但没有客户回复依据，或不适用没写依据。

**完成率**中，"带意见批准"算已批准；但闭环检查要求拿到最终批准。

## 18. 常见问题

**Q：为什么文件上传了，应交项还是"未提交"？**
A：平台分开记两件事：
- **收集情况**：文件上传后马上变成"已收到"，在"收集情况"一列、"收集率"卡片里能看到；
- **提交状态**：表示交没交给客户，要生成传送单（10.1）后才变为"已提交"。

这样能区分"文件到了我们手上"和"已经交给客户"。只想看还没收集到的，点顶部的"收集率"卡片，或在更多筛选里选"收集情况：未收到"。

**Q：智能投递把文件认错了位置怎么办？**
A：存入前在那一行点"选应交项"改位置。已经存进去的，到文件浏览打开文件，点"重新归类"。也可以给文件种类补充"识别关键词"、给设备补充"别名"，以后会认得更准。

**Q：同一份文件我想存成新版本，平台却当成了新文件？**
A：升版要求标题和格式都相同。上传时在"存为"里直接选"某文件的新版本"即可。

**Q：提示"项目里已有内容完全相同的文件"？**
A：这份文件已经在平台里了，提示里有它的名字和版本，不需要重复存。

**Q：客户 MDL 里不想出现某个文件种类？**
A：在项目结构里关掉它的"进客户 MDL"。内部要求一律不会出现。

**Q：客户新加了一个合同外的文件要求？**
A：在项目结构里新建文件种类，要求类别选"客户要求"，依据填客户的函件号，接受情况先是"待确认"，确认后改为接受或不接受。

**Q：我怎么看不到某个项目 / 某个菜单 / 某个按钮？**
A：只有项目成员能看到项目；菜单和按钮按你在项目里的角色显示（1.5）。需要的话请找项目管理员。

**Q：页面顶部有红条"文件存储不可用"？**
A：存文件的磁盘断开了，这时不能上传。请通知 IT 检查外接盘或网络盘，接好后会自动恢复，不需要重新登录。

**Q：误改了设备信息？**
A：设备 → 历史 → "恢复到这次修改之前"。其他对象的修改可以在变更记录里查到修改前的值，再手动改回。

**Q：交付包为什么一直是"排队中"？**
A：交付包、存量导入、镜像同步都由后台服务处理。长时间排队请通知 IT 检查 docbase worker 服务。

**Q：被挤进回收区的旧版本还能拿回来吗？**
A：90 天内可以在文件浏览 → 回收区下载。

## 19. 术语表

| 术语 | 说明 |
|---|---|
| MDL | Master Document List，应交文件清单；平台的项目结构导出给客户的版本 |
| 里程碑 | 项目阶段，如 M3 详细设计；带截止日期 |
| 文件种类 | MDL 的一行，如"3.5 Cut sheet"；编号按文本处理 |
| 模块 | 文件种类的分区 |
| 设备条目 | 一类设备 + 台数 |
| 应交项 | 一个"应该交的文件"的位置：种类 × 设备 / 模块 |
| 收集情况 | 平台里有没有这一项的文件：已收到 / 未收到（自动判断） |
| 缺件 | 还没收到文件的（不算已批准、不适用的）+ 客户要求修改重交的 |
| 文件 / 版本 | 挂在应交项上的一个文件；每次上传是一个版本，只增不改 |
| 来源 | 文件来自客户、供应商还是我方 |
| 传送单 | 一次提交给客户的记录（Transmittal），带编号 |
| 审核代码 | 客户审核结论的标记，如 1 批准、3 修改重交 |
| 视为批准 | 客户超期未回复，按合同条款视为批准 |
| 无凭证 | 状态是手改的，没有客户回复依据 |
| 客户要求 | 合同外客户新增的文件要求，有接受情况和变更单号 |
| 待归类 | 存进来但还没有位置的文件 |
| 回收区 | 超出保留版本数的旧版本，90 天后删除文件 |
| 阶段基线 | 某一时刻全部应交项状态和文件版本的快照 |
| 交付包 | 按目录结构打好的 zip，附文件清单 |
| 共享盘镜像 | 最新版文件同步到共享盘上的只读文件夹 |
| 存量导入 | 把已有的旧文件夹批量导入平台 |
| 闭环 | 里程碑的每个应交项都有最终结论和凭证 |
